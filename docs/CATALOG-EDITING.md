# Owner catalog workflow

Open `/kelola-katalog` or use **Editor katalog** in the footer. This is a public, noindex workbench for preparing content revisions. It is not a private CMS or a direct publishing endpoint. No credentials or customer data belong here. Existing machine measurements, 3D assets, exact variant photos and technical verification are outside this editor.

1. Select a machine family. Edit Indonesian and English names, descriptions, configuration names/notes, IDR prices, price status and availability. Stable product/variant IDs cannot be changed in the interface. The preview reflects the selected language.
2. Drafts save only in the current browser under `hcbtech-catalog-draft-v1`, separately from buyer inquiries. They survive reloads when local storage is available. Reset returns to the published data. Export a reviewed revision before clearing browser storage or moving devices.
3. Enter a public review attribution, review date and public source note. Check both languages, prices and availability, then acknowledge the review and export `hcbtech-catalog-update.json`. Importing a revision brings it back into the workbench and clears the acknowledgement for another review. Exporting does not change the public catalog.
4. In the project, run `npm run catalog:import -- /path/to/hcbtech-catalog-update.json --check`. Inspect the source note and values in the JSON, and compare them with the owner's source material. The command defaults to check-only; it does not write files.
5. Apply the reviewed revision with `npm run catalog:import -- /path/to/hcbtech-catalog-update.json --apply`. It writes only `assets/catalog-content.json` and its public provenance copy, `public/docs/catalog-update.json`. Original price-sheet transcription, photographs, model files, route IDs and technical specifications remain separate.
6. Review the Git diff and run `npm run check`, `npm run test:browser` and `npm run test:production`. Publish the reviewed commit through the existing Vercel workflow. A Git push alone does not prove this project has deployed; verify the deployed source commit, source-file package and buyer inquiry links.

The browser, build and import command share the same strict validator. It requires all three known families and all fourteen correct variant IDs; both languages; whole, positive IDR prices or `null`; valid price/availability states; a real calendar date; and review provenance. Duplicate IDs, unknown fields, geometry changes, incomplete records, oversized input and confirmed-but-missing prices are rejected. `--check` is suitable for validating an export without changing the catalog. The input cannot select output paths.

At runtime, a reviewed content file updates copy and variant prices/status in both languages and changes the linked price source to the public revision file. It does not upgrade model accuracy, technical specifications or exact photo associations. Reference/confirmed price status also survives the quotation handoff. No catalog values were changed when this workflow was introduced; `assets/catalog-content.json` starts empty.

Direct authenticated publishing, media uploads, revision approvals, server-side inquiry storage and business analytics are future phase-4 work. They need an owner access model and service configuration. The current workbench has no server writes, authentication, inquiry queue or tracking.
